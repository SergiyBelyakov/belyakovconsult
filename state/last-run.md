A value can pass every format check and still lead to the wrong payment decision.

Most public registers control syntax well: input masks, mandatory fields, exchange schemas. It is the easiest part to automate, so the quality conversation usually ends here.

ISO 8000-8 suggests looking wider and distinguishes three levels of data quality:
• syntactic: does the data conform to its format, structure, encoding
• semantic: does it correspond to what it represents, by definition and code list
• pragmatic: is it fit for the purpose of the people who use it

The first two levels can be checked against a specification or a code list. The third cannot be judged without the data users: only they know what is enough for their decision.

For registers that underpin administrative decisions and exchange between agencies, this difference has a price. A code with a valid format but from another version of a classification passes the exchange unnoticed. A year-old address is fine for an annual report and wrong for a monthly payment.

Start with one critical field and three checks instead of one completeness percentage.
