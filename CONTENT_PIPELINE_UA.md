# Конвеєр контенту Belyakov Consult

Один матеріал на тиждень → сторінка на сайті + LinkedIn (UA, EN) + Threads + Telegram + карусель для Instagram.
Усе працює безкоштовно на GitHub Actions. Нічого не публікується без вашого затвердження.

## Як це працює

```
Ідея (тези, голосова нотатка)
  → Claude готує пакет файлів за prompts/content-pack.md
  → запит на зміни (Pull Request) у GitHub
  → автоматична перевірка: ліміти символів, розклад, тестова збірка сайту
  → ви читаєте, правите прямо в GitHub і натискаєте «Merge» = затверджено
  → щогодини конвеєр публікує те, час чого настав
  → щопонеділка — дайджест у Telegram
```

Що робить кожен файл:

| Файл | Призначення |
| --- | --- |
| `config.yml` | Усі налаштування: режим, сайт, мови, канали, послуги |
| `content/articles/<slug>/uk.md`, `en.md` | Стаття для сайту |
| `content/articles/<slug>/posts/*.md` | Дописи для соцмереж з датою і часом |
| `prompts/style.md`, `prompts/content-pack.md` | Голос бренду та інструкція для Claude |
| `scripts/build_site.py` | Сторінки статей, список, RSS, sitemap, картинки |
| `scripts/publish.py` | Публікація в LinkedIn, Threads, Telegram; Instagram — через адмінку |
| `scripts/validate.py` | Перевірка перед затвердженням |
| `scripts/digest.py` | Щотижневий звіт у Telegram |
| `state/published.json` | Журнал: що і коли вийшло (захист від дублів) |
| `site/insights/…` | Згенеровані сторінки статей (не редагуйте вручну) |

## Захист від помилок

- **Режим `dry-run` за замовчуванням.** Поки в `config.yml` не стоїть `mode: live`, у соцмережі не йде нічого — лише повідомлення «вийшло б ось це» вам у Telegram.
- Допис зі `{{link}}` чекає, поки стаття з’явиться на сайті.
- Кожен допис публікується щонайбільше один раз.
- Якщо конвеєр стояв і допис прострочений більше ніж на 48 годин, він не вийде сам — ви отримаєте повідомлення. Щоб опублікувати, змініть `publish_at`.
- Після 3 невдалих спроб допис зупиняється, причина приходить у Telegram.
- Якщо для каналу немає токена, текст приходить вам у Telegram для ручної публікації.

## Налаштування (≈1,5 години один раз)

### 1. Репозиторій

Конвеєр живе в тому ж репозиторії, що й сайт: код сайту в `site/`, конвеєр поруч (`content/`, `scripts/`, `templates/`, `prompts/`, `config.yml`, `.github/`). Спершу він працює в тестовому `belyakovconsult_digital`, потім переноситься в `belyakovconsult` тим самим набором файлів.

1. Settings → Actions → General → Workflow permissions → **Read and write permissions** → Save.
2. Розклад запусків GitHub вмикається лише для гілки за замовчуванням, тобто після Merge у `main`.

### 2. Telegram (адмінка і канал)

1. У Telegram відкрийте @BotFather → `/newbot` → отримаєте токен бота.
2. Створіть публічний канал (наприклад `@belyakov_data`), додайте бота адміністратором з правом публікації.
3. Напишіть своєму боту будь-яке повідомлення, потім відкрийте в браузері
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` і знайдіть `"chat":{"id": …}` — це ваш ID для адмінки.
4. У GitHub: Settings → Secrets and variables → Actions → **New repository secret**:
   - `TELEGRAM_BOT_TOKEN` — токен бота
   - `TELEGRAM_CHANNEL_ID` — `@belyakov_data`
   - `TELEGRAM_ADMIN_CHAT_ID` — ваш ID з кроку 3

Після цього вже працюють тестові повідомлення, дайджест і ручна публікація в усі мережі.

### 3. LinkedIn (особистий профіль)

1. Застосунок LinkedIn обов’язково прив’язується до сторінки компанії. Якщо її ще немає — створіть сторінку Belyakov Consult (вона ж знадобиться для бренду).
2. linkedin.com/developers → Create app → прив’яжіть сторінку.
3. Вкладка Products → додайте **Share on LinkedIn** і **Sign In with LinkedIn using OpenID Connect**.
4. Вкладка Auth → OAuth 2.0 tools → Token generator → оберіть `openid`, `profile`, `w_member_social` → згенеруйте токен.
5. Секрет `LINKEDIN_TOKEN` — цей токен. Змінна (вкладка Variables) `LINKEDIN_TOKEN_DATE` — сьогоднішня дата `РРРР-ММ-ДД`.

Токен LinkedIn діє 60 днів і автоматично не продовжується. За 14 днів до закінчення дайджест нагадає повторити крок 4. Якщо токен сплив, дописи для LinkedIn приходитимуть у Telegram для ручної публікації.

### 4. Threads

1. developers.facebook.com → Create app → сценарій **Access the Threads API**.
2. Дозволи: `threads_basic`, `threads_content_publish`. Додайте свій акаунт Threads як тестувальника і прийміть запрошення в налаштуваннях Threads.
3. Graph API Explorer (перемкніть на `threads.net`) → Generate Token → обміняйте на довготривалий (60 днів).
4. Секрет `THREADS_TOKEN`, змінна `THREADS_TOKEN_DATE`.

Щоб токен Threads продовжувався сам: github.com → Settings → Developer settings → Fine-grained tokens → доступ лише до цього репозиторію з правами **Secrets: Read and write** і **Variables: Read and write** → збережіть як секрет `GH_PAT`.

### 5. Instagram

Конвеєр готує картки 1080×1350 і підпис та в день публікації надсилає їх альбомом вам у Telegram. Збережіть картинки на телефон і опублікуйте каруселлю — це 2 хвилини. Автопублікація через API Instagram можлива, але потребує бізнес-акаунта й окремого застосунку Meta; варто додавати, коли решта стабільно працюватиме.

### 6. Сайт

Конвеєр пише прямо в `site/`:

- `insights/<slug>/`, `en/insights/<slug>/`, `pt/insights/<slug>/`: сторінки статей з canonical, hreflang, Open Graph і розміткою Article;
- `insights/index.html` у трьох мовах: список матеріалів (нинішні сторінки з 4 нотатками замінюються, усі нотатки перенесені);
- `insights/feed.xml`: RSS; `sitemap-insights.xml`: окрема карта для статей (рядок про неї автоматично додається в `robots.txt`);
- `assets/insights/`: стилі статей, прев’ю для соцмереж і картки каруселі.

Шапка, підвал, форма зв’язку й стилі беруться з вашої сторінки `cases/` під час кожної збірки. Якщо змінити дизайн сайту, статті підхоплять його самі.

**Важливо про `deploy_main.sh`.** Цей скрипт синхронізує репозиторій з локальною папкою з ключем `--delete`, тобто видаляє все, чого немає локально. Після підключення конвеєра він зітре статті, журнал публікацій і сам конвеєр. Перед наступним використанням спочатку зробіть `git pull`, щоб локальна копія містила все з GitHub, або оновлюйте сайт звичайним комітом.

Після першого викладення подайте `https://www.belyakovconsult.com/sitemap-insights.xml` у Google Search Console.

### 7. Перший запуск

1. Actions → **Конвеєр контенту** → Run workflow. За хвилину в Telegram прийде тестове повідомлення (якщо час якогось допису настав) або нічого — журнал видно в самому запуску.
2. Перший тиждень залиште `mode: dry-run` і порівнюйте повідомлення з тим, що хотіли б бачити.
3. Змініть у `config.yml` на `mode: live` і закомітьте.

## Щотижнева робота (≈2–3 години)

1. Надиктуйте або напишіть тези в чат Claude і попросіть: «зроби пакет контенту за prompts/content-pack.md».
2. Claude створює гілку й Pull Request (якщо репозиторій підключено до Claude) або віддає файли, які ви завантажуєте в нову гілку.
3. Перевірка запускається сама: вкладка Checks → Summary показує помилки, попередження і розклад. Архів `preview-site` — зібраний сайт для перегляду.
4. Правите текст прямо в GitHub (олівець на файлі) і натискаєте **Merge**.
5. Відповідаєте на коментарі в соцмережах — цього конвеєр не робить і не повинен.

## Перевірка локально (необов’язково)

```
pip install -r scripts/requirements.txt
python scripts/validate.py
python scripts/build_site.py
python scripts/publish.py --dry-run
```

`PIPELINE_NOW="2026-10-28 10:00"` перед командою імітує інший час.

## Витрати

Нуль. GitHub Actions для приватного репозиторію дає 2 000 хвилин на місяць; щогодинний запуск забирає близько 720. API Telegram, LinkedIn і Threads безкоштовні. Шрифт Inter (у `fonts/`) — вільна ліцензія OFL.

## Що можна додати пізніше

- Автопублікацію в Instagram через API.
- Заявки з форми сайту → Telegram і таблиця (безкоштовно через Cloudflare Workers).
- Дані Search Console і переходи з соцмереж у щотижневий дайджест.
