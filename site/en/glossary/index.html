Glossary: data, BI and analytics in plain words

Short definitions of the terms I use in my articles, from data quality and governance to Power BI and Microsoft Fabric. Each term explains why it matters for the business and where to read more.

ABCDEFIKLMOPQRSTV
AAnalytics engineerA role between data engineer and analyst that turns data into analysis-ready models as code (SQL, dbt), with tests and versions in Git. BBI (business intelligence)The processes and tools that turn a company's data into reports, dashboards and measures for decision making. CCardinalityThe number of distinct values in a column. IDs, second-level timestamps and free text have high cardinality. CCDC (change data capture)A way to pass on only the changes in a source database, usually by reading its transaction log, instead of copying whole tables. CCompletenessThe share of required fields or records that are filled in. One of the dimensions of data quality. CComposite modelA Power BI semantic model where some tables use Import and others use DirectQuery. DDashboardAn interactive panel that brings key measures and charts together for a quick view of how things stand. DData architectureA description of where data comes from, where and in what shape it is stored, how it is transformed and how it reaches reports and systems. DData engineerA specialist who builds and runs integrations, load pipelines and data stores: ETL and ELT, orchestration, monitoring. DData fabricAn approach that builds a layer of metadata, catalogue and virtual access on top of existing systems to automate finding, integrating and controlling data. The term is promoted by Gartner and vendors. DData freshnessHow long ago the data in a report was received from its source. A page refresh time shows when the page ran, not when the data arrived. DData governanceThe rules, roles and processes that decide who is responsible for data, how it is defined, who has access and how disputes are settled. DData lakeStorage for large volumes of raw data in any format, usually in low-cost cloud file storage. DData martA part of the warehouse prepared for one business area, such as finance or sales, usually as a star schema. DData meshAn organisational approach where business domains own the data they create and publish it as data products on a shared platform under shared rules. DData ownerA business person responsible for the definitions, quality and access rules of the data in their area. DData productA dataset a team publishes for others with a description, an owner, guaranteed quality and a clear way to access it. DData qualityHow fit data is for its purpose: complete, accurate, consistent, timely and free of duplicates. DData snapshot and cut-off dateA saved state of data as of a specific date (the cut-off date) that no longer changes, even if the source is corrected later. DData stewardA person who looks after data quality in their area day to day, resolving errors, duplicates and disputed records under the data owner's rules. DData warehouseA separate database where data from different systems is collected on a schedule and reconciled for analytics and reporting. DDAXData Analysis Expressions, the formula language of Power BI and Analysis Services for measures and calculations in the model. DdbtAn open tool for transforming data inside the warehouse: models are written as SQL code with tests, documentation and versions in Git. DDelta (Delta Lake)An open table format on top of Parquet files with a transaction log, giving reliable changes and version history. In Microsoft Fabric it is the standard table format in OneLake. DDeployment pipelineThe Power BI and Fabric feature for moving content between development, test and production workspaces. DDimension tableA table describing what facts are analysed by: customers, products, departments, dates. DDirectQueryThe Power BI mode in which data is not copied and every report interaction sends a query straight to the source. DDirect LakeA semantic model mode in Microsoft Fabric where the Power BI engine reads data straight from Delta tables in OneLake without a separate import. DDuplicate recordSeveral records in one system describing the same thing, such as one person or one contract. EELTExtract, Load, Transform. Data is loaded into the warehouse as is and transformed inside it, often as code (for example in dbt). EETLExtract, Transform, Load. Data is extracted from sources, transformed and only then loaded into the warehouse. FFabric capacity (F SKU)A sized pool of Microsoft Fabric compute that workspaces run on. Microsoft no longer sells new Power BI Premium capacities (P SKUs); F SKUs replace them. FFact tableA table of events or transactions and their numeric values: sales, payments, shipments. Each row is one event. FFTE (full-time equivalent)A unit of workload equal to one person working full time. IImport modeThe Power BI mode in which data is copied into a compressed in-memory model and refreshed on a schedule. IIncremental refreshA Power BI setting where only new or changed periods are reloaded during refresh, while history stays as it is. IISO 8000A series of international standards on data quality, including master data quality and exchanging data between organisations. KKPI (key performance indicator)A measure a company or team uses to judge whether it is reaching its goals. LLakehouseAn architecture that combines a data lake and a warehouse: data sits in an open table format (such as Delta) and serves both engineering and reporting. LLive connectionA way for a Power BI report to connect to an already published semantic model or Analysis Services without copying data or changing the model. LLookerA Google Cloud BI platform where measures are defined as code in the LookML semantic layer and queries run directly against the data warehouse. MMeasure (Power BI)A DAX formula that calculates a value at query time, respecting the report's filters, such as revenue or margin. MMedallion architecture (Bronze, Silver, Gold)Splitting data into layers by readiness. Bronze is raw, Silver is cleaned and reconciled, Gold is ready for reports and analysis. MMicrosoft FabricMicrosoft's analytics platform that brings data engineering, warehousing, lakehouse, Power BI and other tools together around the shared OneLake storage. OODS (operational data store)A separate database holding a copy of operational system data, refreshed on a schedule or in near real time. Reports read the copy, not the live system. OOneLakeMicrosoft Fabric's single logical data store for the whole organisation, where tables are kept in the open Delta format. PPBIP and TMDLThe Power BI Project format (PBIP) stores a report and model as text files; TMDL is the text language that describes a semantic model. PPoint-to-point integrationConnecting each system or report directly to each source separately, with no shared layer in between. PPower BIMicrosoft's BI platform for data modelling, reports and dashboards, now part of Microsoft Fabric. PPower QueryThe data preparation tool in Power BI and Excel, using the M language: connecting to sources, cleaning, combining tables. QQlikA BI platform (Qlik Sense, Qlik Cloud Analytics) with an associative engine: click any value and see what is related to it and what is not. QQuery foldingPower Query's ability to translate transformation steps into a query to the source, so filters and joins run there rather than in Power BI. RRow-level security (RLS)Rules in the semantic model that limit which rows of data a user can see, for example only their own region. SSAP Analytics CloudAn SAP cloud service that combines BI, planning and predictive analytics in one tool. SSelf-service BIAn approach where business users build their own reports and analyses without a development team for every request. SSemantic modelThe layer between data and reports that defines tables, relationships, measures and access rules. In Power BI it used to be called a dataset. SSpark (Apache Spark)An open engine for distributed processing of large data volumes. In Microsoft Fabric it runs notebooks and jobs for the lakehouse. SStar schemaA way to organise data for analytics: a fact table in the centre, surrounded by dimension tables linked one-to-many. SStreamingProcessing data event by event as it arrives rather than in scheduled batches. Classic patterns are Lambda and Kappa. TTableauA Salesforce BI platform for visual data analysis and dashboards, known for flexible charting. VVertiPaqThe in-memory columnar engine behind Power BI and Analysis Services models. It compresses data and evaluates DAX quickly in Import and Direct Lake modes.
